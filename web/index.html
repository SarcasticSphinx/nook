Sorting algorithms

notes, week 6

1. Insertion sort

Build the sorted part one element at a time: take the next element and shift it left past every larger element until it sits in place.

Time O(n²) in the worst and average case, but O(n) when the input is already almost sorted. Extra space O(1). Stable.

2. Merge sort

Split the array in half, sort each half recursively, then merge the two sorted halves with two pointers.

Time O(n log n) in every case. Needs an O(n) buffer for merging. Stable, and the natural choice for linked lists.

3. Quicksort

Pick a pivot, partition so smaller items end up on the left and larger ones on the right, then recurse on both sides.

Average O(n log n), worst case O(n²) when the pivots are bad (for example, always the first element of input that is already sorted). Not stable. A random pivot or median-of-three avoids the worst case in practice.

4. Heapsort

Turn the array into a max-heap, then repeatedly swap the root to the end and sift the new root down.

Always O(n log n), O(1) extra space, not stable.

Which one when

  • Small or nearly sorted input: insertion sort.
  • Need stability, or sorting a linked list: merge sort.
  • General in-memory sorting: quicksort (most standard libraries use a hybrid of it).
  • Tight memory and a guaranteed worst case: heapsort.
